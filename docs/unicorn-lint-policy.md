# Unicorn rule policy

As reviewed on 23 November 2026: **22 enabled**, **116 disabled** among **138 rules registered by Oxlint 1.94.0**. The registered list includes the `filename-case` compatibility placeholder. Every registered Unicorn rule has an explicit setting; category defaults cannot silently activate another reviewed rule.

The wider upstream README links **380 rule names** at revision [`f2242f762b5a`](https://github.com/sindresorhus/eslint-plugin-unicorn/tree/f2242f762b5a3b2a3aaaaf5be2eb069ed2f77f3b). **247** of those names are not registered by this Oxlint version. The two tables cover **385 distinct names**, including five older names retained by Oxlint. This is a versioned inventory, not a claim that every upstream ESLint rule is available natively.

The 1.94.0 upgrade retains the same 138 registered Unicorn rule names as the
previous 1.86.0 review. Registry comparison and real-linter fixtures pass; the
22 enabled checks and all explicit off settings remain unchanged.

## Selection

Enable focused correctness checks for listeners, fetch options, shared array references, accessors, promise misuse, constructor mistakes, and window message origins. A few low-cost allocation improvements and unambiguous Node/keyboard APIs are also enabled. Keep pure model transformations, explicit nulls, local closures, runtime parsing and existing module boundaries. No ESLint dependency or runtime package is added.

The listener rule catches incorrect removal references; it does not prove a listener is eventually removed, check pre-aborted signals, or guarantee timer/response-body cleanup. Those need lifecycle tests. The existing bounded formatter cache needs allocation/eviction regressions; Unicorn has no direct bounded-cache rule. The separate issue PRs address the actual retention findings.

An initial scan of the selected rules found eight diagnostics. Six were inappropriate `innerText` diagnostics on Playwright Locator methods, and one rejected the valid `export {}` marker in a declaration file; those two rules remain disabled for the reasons below. The remaining filtered-array/last-element lookup now uses `findLast`, preserving behavior without allocating an array.

The machine-readable decisions are in [`tooling/unicorn-policy.json`](../tooling/unicorn-policy.json); the wider collection snapshot is in [`tooling/unicorn-upstream.json`](../tooling/unicorn-upstream.json). Tests compare the pinned registry with this policy and exercise positive/negative fixtures through the real Oxlint executable. On a tool upgrade, review new rules and update the inventory before changing their settings.
