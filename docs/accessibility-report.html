Accessibility audit

Completed 33 Chromium tests: 19 passed, 14 failed on accessibility assertions. Every planned scan completed; there were no skipped tests or flow/setup failures. The 38 affected scans include 19 with WCAG-tagged violations. Repeated screens and profiles account for 148 affected-element observations; these are not 148 independent defects.

What to fix first

Finding Evidence Suggested change
Vortoj · button names Score and rack buttons fail label-content-name-mismatch in all three profiles. Visible “Your score 0 points” is replaced by “Players, scores and game details”; tile letter/point text also differs from the name. Keep visible wording in the accessible name, including its order; use descriptions for extra context. Review tile letter/point markup as well as aria-label. WCAG 2.5.3.
Kunludo · text contrast “Dein erstes Team wartet.” measures 2.77:1 in light mode and 3.86:1 in dark mode; small text needs 4.5:1. Increase contrast of the empty-account heading in both default themes. WCAG 1.4.3.
Enigmo · text contrast Puzzle help text measures 3.42:1 in light desktop/mobile, below 4.5:1. Use a darker light-theme help-text color. The dark profile did not report this violation. WCAG 1.4.3.
Vortoj · text contrast Muted headings/status text measures 4.08:1 on the light background, below 4.5:1. Affects sign-in, lobby/editor and active play. Adjust the light-theme muted text color, then rescan all uses. WCAG 1.4.3.
Shared navigation · duplicate banners The desktop menu’s header[data-panel-heading] is exposed as another banner in Vortoj and Kunludo. Two axe rules flag the same structural issue. Use a neutral panel heading/container where appropriate, preserving one page banner. Best practice.
Kunludo · account landmarks Entry, code and name screens lack a main landmark. Content is reported outside landmarks in every profile. Wrap the account screen’s primary content in main. Best practice.
Kunludo · mobile headings Empty account, create-team, teams and calendar-selection screens have no exposed level-one heading on mobile. Keep the page-purpose h1 available in the mobile main content, including when navigation is closed. Best practice.
